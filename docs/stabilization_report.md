# Исправления и проверка AITruckRadio

Дата: 18 сентября 2026. Изменения находятся в рабочей копии, без коммита.

## Исправлено

- `never_block_for_dj` теперь имеет приоритет над синхронной подготовкой очередной вставки в live-эфире. Отдельная настройка ожидания стартового вступления сохранена.
- Чтение FFmpeg вынесено в `AudioProcessRunner`: stdout и stderr читаются независимо, очереди и журнал ограничены, Stop/Skip прерывают ожидание даже при отсутствии аудио. При отсутствии данных дольше `ffmpeg_idle_timeout_sec` (по умолчанию 30 секунд) текущий элемент пропускается с диагностикой.
- Повторный запуск не разрешается, пока предыдущий поток эфира ещё завершает работу.
- Сохранение настроек сериализовано. Папки музыки и кэша, список треков, NewsAgent, клиент модели, TTS и хранилище плана обновляются в работающем движке. Старые зарезервированные треки сбрасываются при смене папки музыки.
- Значения громкости голоса/подложки, loudness и времени перехвата больше не заменяются принудительно на прежние миграционные значения. Некорректные числа восстанавливаются из значений по умолчанию. API возвращает фактически применённые значения.
- Очистка TTS-кэша учитывает текущий и следующий планы, собираемый план, подготовленную вставку и передаваемое аудио. Ссылки из сохранённых планов также защищены. Во время синтеза диалога очистка откладывается до склейки всех голосов.
- Отменённая генерация шоу-плана освобождает зарезервированные ресурсы и удаляет только свои ещё не опубликованные MP3 из speech-кэша.
- Загрузка multipart-аудио использует MIME-парсер и сохраняет завершающие байты CR/LF исходного файла.
- Проверка loopback/Host/Origin распространяется на HTML-панель и GET API. Аудиопоток `/stream.mp3` сохраняет доступность для внешнего плеера.
- Веб-исследователь проверяет адрес каждого HTTP-перенаправления до обращения к нему. Публичные перенаправления продолжают работать.
- Для пустого ответа в компактной генерации ведущего после исчерпания лимита рассуждения добавлен один ограниченный повтор с `reasoning_effort=none`. Скрытое рассуждение не используется как текст эфира.
- Режим `tts_backend=none` больше не создаёт ложную ошибку синтезатора.
- Миграция старых конфигураций больше не перезаписывает явно выбранные `none`, `sapi`, `piper` и другие TTS-бэкенды; OmniVoice назначается только при отсутствии/legacy-значении.
- MP3-подписчики вынесены в `StreamBroadcaster`; повторный `remove_subscriber` стал идемпотентным и больше не портит счётчики других слушателей.
- Статус TTS теперь проверяет реальные prerequisites SAPI/Piper/Silero и сообщает `missing_model`, `missing_executable` или `missing_helper` вместо ложного `ready`.
- Piper удаляет устаревший WAV перед каждым запуском и корректно убирается при таймауте.

## Проверки

- Pytest: **207 passed, 12 subtests passed**; добавлены регрессионные сценарии потоковых подписчиков, миграции TTS и readiness-бэкендов.
- Покрытие Python-кода: **52%** (до работы — 44%). Это покрытие автоматическими тестами, а не оценка готовности продукта.
- Ruff, Pyright, Bandit, компиляция Python и `git diff --check` прошли.
- Проверены настоящий дочерний процесс без stdout, прерывание Stop/Skip, таймаут и заполненный stderr.
- Реальный короткий запуск движка с установленным FFmpeg: получены MP3-данные, Skip сменил трек, Stop завершил поток, `last_error` пуст. Для этой проверки использовались отдельный временный кэш и настройки в памяти; LLM/TTS были отключены.
- Изолированный smoke встроенного Windows SAPI: русская фраза преобразована в MP3 размером 83635 байт без fallback и ошибок; пользовательский `config.json` не изменялся.
- Плановый эфир в изолированной SAPI-конфигурации собрал 4 элемента (2 speech + 2 music), все аудиофайлы пригодны для воспроизведения.
- Браузерный smoke-сценарий на изолированном локальном HTTP-сервере: открытие панели, сохранение системных настроек, запуск эфира с подтверждениями, смена трека через Skip и остановка эфира.
- Расширенный изолированный browser smoke: изменение bitrate и сохранение настроек, раскрытие секции reference voice, переход к генерации плана и проверка защитного подтверждения перед тяжёлым OmniVoice; тяжёлый backend намеренно не запускался.
- Пользовательский `config.json` не изменён. Запущенные проверками процессы завершены.

## Осталось проверить и доработать

1. Длительный прогон с тяжёлым TTS: SAPI и Piper прошли изолированные smoke-тесты (MP3 создаётся, длительность проверена через ffprobe); часовой Gemma/API/радио/MP3-прогон выполнен с `tts_backend=none`. OmniVoice/Qwen/F5 и GPU-устойчивость требуют отдельного аппаратно-зависимого запуска.
2. Полный browser-flow с фактической загрузкой reference voice, генерацией/редактированием плана, прослушиванием и перезапуском требует доступного тяжёлого TTS; интерфейс и защитное подтверждение проверены в изоляции.
3. Продолжить выделение независимых компонентов из `engine.py`: жизненный цикл эфира, построение плана, управление конфигурацией. Подписчики MP3 уже вынесены в отдельный `StreamBroadcaster`; сам `engine.py` всё ещё остаётся крупным модулем.
4. Расширять интеграционные тесты настоящих TTS-бэкендов: нынешние проверки кэша/склейки и SAPI smoke не подтверждают качество русского произношения или устойчивость GPU-синтеза.

Диапазонная проверка настроек теперь централизована в `settings_schema.py` и применяется к API после приведения типов; добавлены регрессионные проверки для порта, вероятностей и коэффициентов.

Исправлены перечисленные воспроизводимые дефекты. Оснований утверждать, что в проекте устранены абсолютно все ошибки, пока нет.
