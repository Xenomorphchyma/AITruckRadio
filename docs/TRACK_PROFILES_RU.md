# Профили треков

Профили треков нужны, чтобы ведущие понимали музыку, не выдумывали факты и не путали следующий/предыдущий трек.

Файл создаётся тут:

`cache\track_profiles.json`

Запуск из панели:

`Музыка и факты → Сгенерировать/обновить описания музыки`

Запуск вручную:

`scripts\tracks\build_track_profiles.bat`

По умолчанию используется режим `web_agent`:

1. Скрипт разбирает имя файла на исполнителя и название.
2. Локальная модель в LM Studio составляет несколько поисковых запросов.
3. Скрипт получает обычную веб-выдачу и читает текст наиболее подходящих страниц.
4. LM Studio пересказывает и сокращает найденные сведения под радиоведущего, а не копирует страницы.
5. Отдельный проход модели удаляет факты, которые не подтверждаются прочитанными материалами.
6. Профиль сохраняется по схеме `radio_track_profile` вместе с URL и служебными выдержками для проверки.

Основные настройки:

- `track_profiles_research_mode`: `web_agent` или старый `legacy_apis`;
- `track_profiles_agent_max_queries`: число поисковых запросов на трек;
- `track_profiles_agent_max_pages`: число читаемых страниц;
- `track_profiles_agent_page_chars`: лимит очищенного текста одной страницы;
- `track_profiles_agent_total_evidence_chars`: общий лимит текста всех страниц для одного запроса;
- `track_profiles_agent_page_timeout_sec`: таймаут загрузки страницы.

Рекомендуется начинать с 3–4 запросов и 3–4 страниц. Полная пересборка большой библиотеки занимает заметное время, потому что на каждый трек выполняются поиск, чтение страниц, составление профиля и фактчекинг.

Если веб-поиск недоступен, профиль всё равно создаётся по имени файла, но получает `research_status: unverified`. Ведущим нельзя выдавать такой профиль как источник исторических или биографических фактов.
